# Workflow 06 — Onboard an existing project

## Purpose

You have a project that was not created from the MASTERMIND template. It may have code, commits, README, tests, partial docs, and possibly `.cursor/rules/` or `.claude/` from earlier AI work. You want to bring it into the MASTERMIND 2.0 system — with its rules, skills, workflows, commands, hooks, and the memory discipline — without losing any work and without forcing the project back to Idea phase.

This workflow is the canonical path for that scenario. It is deliberately paranoid about not touching code or project-specific content.

## Preconditions

- The target project is on disk with a working git repository (recommended).
- You have access to an up-to-date MASTERMIND 2.0 template on disk.
- You know roughly what phase the project is in (Idea / Discovery / Definition / MVP / Iteration / Launch). If unsure, err on the conservative side; the phase can be adjusted with `/mm-gate` later.
- Cursor / Claude are **closed** on the target project for the shell-install step.

## Phases

### Phase 1 — Prep (Executor, manual)

- **Skill:** _(manual)_
- **Mode:** Executor
- **Input:** the target project.
- **Steps:**
  1. `cd` into the target project.
  2. `git status` — commit or stash any pending work: `git add . && git commit -m "wip: checkpoint before MASTERMIND onboarding" && git push` (or just commit locally if no remote).
  3. Close Cursor, Claude Desktop, Claude Code sessions on this project. Leave nothing open that could race with file writes.
  4. Copy the two onboarding scripts into the target project's `scripts/` folder:
     ```powershell
     New-Item -ItemType Directory -Force -Path "<project>\scripts" | Out-Null
     Copy-Item "<template>\scripts\onboard-existing-project.ps1" -Destination "<project>\scripts\" -Force
     Copy-Item "<template>\scripts\onboard-existing-project.sh"  -Destination "<project>\scripts\" -Force
     ```
- **Exit criterion:** clean git state; no IA open on the project; scripts available.

### Phase 2 — Install the shell (Executor, scripted)

- **Skill:** _(script `scripts/onboard-existing-project`)_
- **Mode:** Executor
- **Input:** the template path + chosen initial phase.
- **Steps:**
  1. Dry-run to see what would change:
     ```powershell
     pwsh -File scripts/onboard-existing-project.ps1 -Template "<template path>" -Phase <Phase>
     ```
  2. Read the output carefully:
     - `NEW (N)` — files that will be created.
     - `CONFLICTS (M)` — files that already exist with different content; will be written as `<file>.mastermind-proposal`.
     - Pre-existing rules — relocated to `.cursor/rules-backup-YYYYMMDD-HHMMSS/`.
     - Stack auto-detected — pre-fills `02-tech-stack.mdc` from `package.json` lockfiles.
  3. If the list looks right, apply:
     ```powershell
     pwsh -File scripts/onboard-existing-project.ps1 -Template "<path>" -Phase <Phase> -Apply
     ```
     Confirm with `yes`.
- **Exit criterion:** shell installed, phase set in `memory/02-current-state.md` and `memory/13-phase-history.md`.

### Phase 3 — Resolve conflicts (Executor, manual — only if any)

- **Skill:** _(manual)_
- **Mode:** Auditor → Executor
- **Input:** `<file>.mastermind-proposal` files generated by Phase 2.
- **Steps:**
  1. `Get-ChildItem -Recurse -Filter "*.mastermind-proposal"` — list all proposals.
  2. For each: open the pair (original + proposal) in a diff view. Three legitimate outcomes:
     - **Keep the project's file**: delete the `.mastermind-proposal`.
     - **Adopt the MASTERMIND version**: rename `.mastermind-proposal` to overwrite the original; optionally back up the old one first.
     - **Merge**: hand-merge the two into a new version of the original; delete the `.mastermind-proposal`.
  3. Do NOT leave `.mastermind-proposal` files committed to the repo. They are scaffolding.
- **Exit criterion:** zero `.mastermind-proposal` files remain; each conflict resolved with an explicit choice.

### Phase 4 — Commit the shell + reload IDE (Executor, manual)

- **Skill:** _(manual)_
- **Mode:** Executor
- **Steps:**
  1. `git status` → review one more time.
  2. `git add . && git commit -m "chore: onboard existing project into MASTERMIND 2.0"`.
  3. Reopen Cursor on the project. Force a reload: `Ctrl+Shift+P` → *"Developer: Reload Window"*.
  4. Restart Claude Desktop / Claude Code completely.
  5. Sanity: in chat, ask *"List active hooks in this repo"* → expect 4: `pre-task.doubt-surfacer`, `post-task.memory-updater`, `post-merge.docs-refresh`, `post-output.suggest-command`.
- **Exit criterion:** MASTERMIND shell is active and being loaded by the IA layer.

### Phase 5 — Retroactive memory seed (Coach → Executor)

- **Skill:** [`retroactive-documenter`](../../.cursor/skills/retroactive-documenter/SKILL.md)
- **Mode:** Coach (reviews), Executor (writes)
- **Input:** the codebase + the now-installed memory skeleton.
- **Steps:**
  1. In chat: *"Run the `retroactive-documenter` skill"* (or `/mm-onboard`, which also wraps this phase).
  2. The skill reads code, git log, README, dependency files, tests.
  3. For each memory file where it has factual basis, it drafts content and presents it.
  4. You respond `approve` / `edit <changes>` / `skip` per file.
  5. Approved files are written + committed as `docs(memory): retroactive seed for memory/<file>`.
- **Exit criterion:** the code-derivable part of memory/ is seeded. Files that require strategy (brief's non-negotiables, persona detail) are explicitly left as `_TBD_` and flagged.

### Phase 6 — Strategic audit (Coach)

- **Skill:** [`project-deep-audit`](../../.cursor/skills/project-deep-audit/SKILL.md)
- **Mode:** Coach
- **Input:** codebase + seeded memory.
- **Steps:**
  1. Run `/mm-audit` to fill the strategic layer (12 angles, Hard Truth, top 10 risks, top 10 actions).
  2. The audit consumes `~/.mastermind/global/lessons.md` and `pitfalls.md` if they exist — cross-project signals.
  3. Output lands in `docs/product/*`, `docs/architecture/system-map.md` (draft), and `memory/08-known-risks.md` gets a Top 10.
- **Exit criterion:** the project now has a Hard Truth written down and the top 10 risks/actions sitting alongside the factual memory seed.

### Phase 7 — Confirm the phase (Auditor)

- **Skill:** [`phase-gate-reviewer`](../../.cursor/skills/phase-gate-reviewer/SKILL.md)
- **Mode:** Auditor
- **Input:** populated memory/ + recent audit.
- **Steps:**
  1. Run `/mm-gate <phase-you-set>`.
  2. `phase-gate-reviewer` checks entry criteria against the actual state. If the phase set during onboarding was too advanced (or too conservative), the skill suggests revision.
  3. Optionally: if the audit revealed that the project is actually at a different phase than you thought, run `/mm-gate <adjusted-phase>` as a correction. This is logged in `memory/13-phase-history.md`.
- **Exit criterion:** phase in `memory/02-current-state.md` is confirmed by the gate; history has a proper transition entry.

### Phase 8 — First retrospective (optional, recommended for MVP/Iteration/Launch)

- **Skill:** workflow `05-weekly-retrospective` / skill `continuous-learner`.
- **Mode:** Coach.
- **Steps:**
  1. Run `/mm-retro` with the period `since project inception` (or last 30 days, whatever feels right).
  2. The retrospective converts the pre-MASTERMIND era into cross-project lessons. What worked? What failed? Any risk that materialized?
  3. Candidates that pass the 3-part test get promoted to `~/.mastermind/global/` via `/mm-learn`.
- **Exit criterion:** the project's history has been mined for lessons; the global memory gets richer; the project is fully integrated into the MASTERMIND loop.

## Artifacts produced

- Full MASTERMIND shell installed in the target project.
- `memory/02-current-state.md` and `memory/13-phase-history.md` with a real phase.
- Retroactively seeded `memory/00`, `02`, `03`, `04`, `06`, `08` (those with factual basis).
- `docs/product/*` from the strategic audit.
- Decision entries in `memory/07-decisions-log.md` for onboarding, seeding, audit, and phase confirmation.
- Optionally: promoted lessons in `~/.mastermind/global/`.

## Exit criteria (workflow complete)

- [ ] MASTERMIND shell installed; git status clean.
- [ ] Zero `.mastermind-proposal` files remain (all resolved).
- [ ] 4 active hooks confirmed via sanity check.
- [ ] Memory seeded (per file, approve / skip explicitly).
- [ ] Strategic audit done; Hard Truth written.
- [ ] Phase confirmed by `phase-gate-reviewer`.
- [ ] Optional: first retrospective done; lessons considered for global promotion.

## Anti-patterns

- **NEVER:** Run the onboarding script without first closing Cursor and Claude on the project. Race conditions on `memory/` or `.cursor/plans/` are real.
- **NEVER:** Commit `.mastermind-proposal` files. They are scaffolding. Resolve them before the commit.
- **NEVER:** Skip Phase 5 and jump to Phase 6. Without the factual seed, `project-deep-audit` has no grounding and invents context.
- **NEVER:** Force a phase you are not sure about. If you are wrong, `phase-gate-reviewer` in Phase 7 will catch it — or just start with a conservative phase and advance via `/mm-gate` once the audit confirms.
- **NEVER:** Delete the `.cursor/rules-backup-<ts>/` folder immediately. Keep it at least until the first week of normal operation, in case any of your previous rules was non-obvious and worth re-adopting.
- **NEVER:** Treat this workflow as a way to "reset" a healthy project. It is for onboarding, not re-onboarding. If a project is already in MASTERMIND, use `sync-from-template` for updates.
